## 2. Kaggle/HF/GitHub
- yf_dianping：restaurants.csv 243,247 家（仅 restId、name，34,115 家无名）；ratings.csv 4,422,473 条（userId, restId, rating, rating_env/flavor/service, timestamp, comment）；links.csv 给 dianpingId。无城市/地址/经纬度/人均/分类。百度网盘分发，无许可证。HF 镜像 dirtycomputer/yf_dianping。
- Stanford "Users Who Say Ni" https://nlp.stanford.edu/robvoigt/nis/dianping.json.gz （58MB，2017，无许可声明）：5,986 家餐馆、30 万+评论，以点评 shop id 为键；店级 full_name、city、address、category、cost_per、huanjing；评论级 star_rank、kouwei、fuwu、huanjing、text、date_posted、comm_type（抽样 67% 为"团购点评"）。前 711 家城市分布：苏州/天津/重庆/广州/杭州/北京/成都/南京/深圳/上海各 55–80 家，无经纬度。
- HF yushangjinghong/dianping-three-source-merged（2026-09，无 license）：Yongfeng+Stanford+北大粤菜合并 256,549 家/3,518,976 评论，说明 yf_dianping 与 Stanford 可按点评 id 对接。
- Meituan-Dianping/asap（Apache-2.0）：46,730 条评论、18 aspect 情感+星级，无餐厅 id。meituan/DiningBench 是菜品图像 VQA。
- 高德 POI GitHub：均为抓取工具非数据集（Civitasv/AMapPoi 553★ GPL-3；kenneth663/gaode_spider）。

## 推荐建库方案：深圳（备选北京）
理由：唯一无条件开放且字段含主体业态/经营项目/经营场所的全量许可名录；高德配额与城市无关；Stanford 评论深圳占比约 9%（推算约 500 家）；北京名录仅 csv 且字段少，上海需申请。
- 门店主表：高德 POI 2.0 关键字/周边检索（show_fields=business），限南山+福田+罗湖餐饮类，约 3,000 家 → name/type/address/location/tel/rating/cost/opentime。约 600–800 次调用。
- 合规字段：深圳食品经营许可证按 经营者名称+经营场所 模糊匹配 → 许可状态/有效期/主体业态；先用 1 万条下载样本验证匹配率。
- 真实评论：Stanford 深圳子集（推算 ~500 家、~2.5 万条）按店名+地址用高德检索对 POI（~500 次）；再用 dianpingId 接 yf_dianping 多维评分。
- OSM：仅补 cuisine 标签，不作主源。
- 分布先验：Koubei per_pay/score 分档、饿了么 avg_price 用于合成时抽样。
- 合成（全部打 synthetic 标）：团购套餐（名/价/原价/销量/有效期）、抖音侧评分与热度、无评论门店的评论（LLM 生成，数量 ≤ 真实评论）、缺失营业时间/人均、客流分时曲线。
- API 总量：高德 ≤ 1,500 次/月；百度地点检索可选 100 次/日做评分交叉验证；无需抖音/美团接口。
- 规模：约 3,000 门店、真实评论 2.5–3 万条 + 合成评论 ≤ 3 万条、团购 6–9 千条（每店 2–3 个）。
