**高德 POI 编码**
- [下载页](https://lbs.amap.com/api/webservice/download)写 2023-10-13 更新，[zip](https://a.amap.com/lbs/static/code_resource/Amap_poicode.zip) 里的文件是 `V1.06_20230208.xlsx`。
- 中餐有 23 个菜系码（050101–050123）。外国餐厅有意式 050205、法式 050204、牛扒 050211、地中海 050207。
- 缺口：没有西班牙菜，没有烧烤、小吃、奶茶节点。酒吧不在餐饮大类，编码是 080304。
- 快餐厅 050300 下挂了必胜客 050303 和茶餐厅 050305，"西餐店被标成快餐厅"是编码设计本身带来的。

**Overture**（[taxonomy.csv](https://github.com/OvertureMaps/docs/blob/main/static/taxonomy/2026-09-23.0/taxonomy.csv)）：按菜系分层，如 `european > mediterranean > italian > pizza`、`western_european > french`、`iberian > spanish`。chinese_restaurant 下 13 个子类，没有火锅，也没有面馆。

**Foursquare**：中餐下 33 个细类，有 Hotpot 和 BBQ Joint。Italian、French、Spanish、Pizzeria 并列挂在 Restaurant 下，没有"西餐"这一层，Pizzeria 也不归 Italian。[HF 数据集](https://huggingface.co/datasets/foursquare/fsq-os-places)要登录（401），CSV 取自[官方文档页](https://docs.foursquare.com/data-products/docs/categories)的附件。

**OSM**：iD 的 [cuisine.json](https://github.com/openstreetmap/id-tagging-schema/blob/main/data/fields/cuisine.json) 列 104 个常用值，[zh-CN 译名](https://cdn.jsdelivr.net/npm/@openstreetmap/id-tagging-schema@6/dist/translations/zh-CN.json)覆盖 93 个（western=西餐、pasta=意大利面、hotpot=火锅）。

**子代理的判断**：底表用高德 V1.06，缺口（烧烤、小吃、西班牙菜、东南亚总类、面包甜品和咖啡茶饮、酒吧）自定义补；父子结构参照 Overture 的 restaurant 分支，中文命名参照腾讯美食表和 ChinaTravel。Foursquare 和 Yelp 不适合作底表。

## 2 给门店打标准品类

- **规则映射**：现成的只有英文"码→码"表，如 [overturetoosm 的 tags.json](https://github.com/whubsch/overturetoosm/blob/main/scripts/tags.json)（2117 个 Overture 旧类 → OSM tag，MIT）【实测】。050000、050100、050300 三个高德码不能直接映射。
- **embedding 召回 + LLM 选择**：[Soulas 等 2025](https://arxiv.org/abs/2511.13369) 先用 MiniLM 取 top-20 候选类再让 GPT-4o-mini 选，top-1 准确率 57.2% → 72.8%【文档】；[仓库](https://github.com/LilouSoulas/Mapping-of-OSM-and-FS-categories)只有 notebook、没有 LICENSE。叶子类只有几十个时整张表放进 prompt 就行，不需要预筛。
- **受限分类**：ChinaTravel 在 prompt 里写死"必须在 42 个值中选"；InteRecAgent 用 gte-base 取 top-1，把 LLM 产出的值纠正成库里已有的标签。
- **菜名→菜系词表：没找到够用的开放中文资源。** [Wikidata P2012](https://www.wikidata.org/wiki/Property:P2012)【实测 SPARQL】有中文标签的条目 990 个、菜系 273 个，粤菜只有 21 条、意大利菜 43 条，繁简混杂，还混进了餐厅（萨莉亚），CC0，可当种子。[下厨房语料](https://huggingface.co/datasets/xzm1999/XiaChuFang_Recipe_Corpus)【实测前几条】152 万菜谱、30,060 个菜名，没有菜系字段，HF 标 MIT 但是第三方上传，原始授权要核。

## 3 硬条件、软条件怎么拆、怎么合（五个项目读了代码）

- **InteRecAgent**（[RecAI/llm4crs](https://github.com/microsoft/RecAI/tree/main/InteRecAgent/llm4crs)，MIT）：`prompt/tool.py` 让 LLM 把硬条件写成一行 SQL（字符串用 LIKE、尽量用 OR）。软条件 `retrieval/itemcf_tool.py` 只在用户给出种子物品时按相似度过滤，指"像某某"，不是"安静"这类描述。值对齐：`corups/base.py` 用 gte-base 找和 query 最近的 tags 写进表说明，`retrieval/sql_tool.py` 的 `rewrite_sql` 把不存在的列名和 LIKE 值换成 embedding top-1 的已有值。合并：`buffer/base.py` 的 CandidateBuffer 串行收窄（硬过滤 → 相似度 → 排序）。没有层级展开，"西餐"只会对齐到一个最像的标签。
- **LangChain SelfQueryRetriever**（已移到 [langchain_classic](https://github.com/langchain-ai/langchain/blob/master/libs/langchain/langchain_classic/retrievers/self_query/base.py)）：LLM 输出 `{"query": 软条件, "filter": "and(eq(..),lt(..))"}`，由 translator 下推为元数据过滤。允许的值只写在描述里，`fix_invalid` 只删非法属性和比较符、不纠正值。没有层级。
- **LlamaIndex VectorIndexAutoRetriever**（[auto_retriever.py](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/indices/vector_store/retrievers/auto_retriever/auto_retriever.py)）：prompt 改自 LangChain；`extra_filters` 允许代码注入过滤条件（只支持 AND）。没有值对齐和层级。
- **TravelPlanner**（[restaurants/apis.py](https://github.com/OSU-NLP-Group/TravelPlanner/blob/main/tools/restaurants/apis.py)）：只按城市过滤，整张表交给 LLM；菜系只在 `evaluation/hard_constraint.py` 里按子串判，7 个英文菜系。
- **ChinaTravel**（[restaurants/apis.py](https://github.com/LAMDA-NeSy/ChinaTravel/blob/main/chinatravel/environment/tools/restaurants/apis.py)）：`select(city, key, func)`（LLM 写 lambda）、`nearby`（默认 2 km）、推荐菜子串匹配。价格只有 `food_price<=n` 上限，每家店一个菜系。

五个项目都没有品类层级展开，也都没有价格区间。能借的两点：InteRecAgent 把值对齐到已有标签；LlamaIndex 由代码注入过滤条件。

## 4 中文数值区间解析（本机 Python 3.13 venv 实测）

| 输入 | JioNLP 1.5.31 `parse_money` | Duckling | Recognizers-Text 1.0.2a2 | cn2an 0.5.24 |
|---|---|---|---|---|
| 一两百 | **201（错）** | "一两"=50 克，外加 200 | 200 | 不变 |
| 三五百 | [300, 500] | 3 和 500 | 500 | 不变 |
| 100左右 | 100，标 blur，不给区间 | 100，丢了"左右" | 100 | — |
| 两百以内 | **报错** | 200，丢了"以内" | 200 | 人均200以内 |
| 最多两百块 | 报错 | 上限 200 | — | — |
| 200元以下 | 200，标 blur- | 上限 200 | 200 | — |
| 100到200 | [100, 200] | [100, 200] | 两个独立数字 | — |
| 步行10分钟 | — | 时长 10 分钟 | 时长 600 秒；dimension 把"10分"误判成货币 | 十→10 |

- [JioNLP](https://github.com/dongrixinyu/JioNLP)：Apache-2.0，2026-10-16 还在发版。`rule/rule_pattern.py` 后缀只有"以上、以下、左右、上下"，没有"以内"；前缀没有"最多""人均"；`extract_money` 不认"块"，把"200元以内"抽成精确 200，把"一个"抽成 1 元。
- [Recognizers-Text](https://github.com/microsoft/Recognizers-Text)：MIT，PyPI 停在 2019-11，import 报错要把 emoji 钉在 0.6.0；中文 NumberRange 只有 .NET 实现。
- [Duckling](https://github.com/facebook/duckling/blob/main/Duckling/AmountOfMoney/ZH/Rules.hs)：BSD，Haskell；用 rasa/duckling 镜像起服务测过（测完已删）；Python 封装停更；"左右"只返回原值。
- [cn2an](https://github.com/Ailln/cn2an)：MIT，只做汉字数字转阿拉伯数字。
- "步行 10 分钟"换成距离：没有库做，都只给时长。

四个库都不能直接用。

## 5 两路召回怎么合并

- **RRF（k=60，[Cormack 2009](https://plg.uwaterloo.ca/~gvcormac/cormacksigir09-rrf.pdf)）是默认做法。** LangChain [EnsembleRetriever](https://github.com/langchain-ai/langchain/blob/master/libs/langchain/langchain_classic/retrievers/ensemble.py) 支持 `id_key`（设成 amap_id 就按店合并），但同一列表里同 key 的多条会累加，评论段要先按店收敛。LlamaIndex [QueryFusionRetriever](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/retrievers/fusion_retriever.py) 有 RRF、relative_score 等四种模式。
- **先过滤后语义**：InteRecAgent 用 buffer 串行收窄；SelfQuery、AutoRetriever 把过滤下推到向量库。
- **SQLAutoVectorQueryEngine**：用 SQL 结果改写向量查询，最后由 LLM 综合，是答案层合并。
- **按来源配额**：以上源码里都没看到。
- **Coze Studio v0.5.1 自带混合检索**【实测源码】：rrf.go 对各路的 1/(rank+60) 取最大值而不是求和，返回各路原始分再用同一个 MinScore 过滤。

## 子代理的建议

直接复用：高德 `Amap_poicode.zip` 作底表编码；Overture restaurant 分支作父子结构参照；iD `zh-CN.json` 的菜系译名；ChinaTravel 42 个标签作大类命名对照；Wikidata P2012 作菜名种子；cn2an 做数字归一；RRF 和 `id_key` 的写法（20 行左右，不必引入 LangChain）；InteRecAgent 的值对齐思路（先查同义词表，查不到再用 embedding 最近邻）。

自己写：品类表（code、name、parent、level、amap_typecodes、synonyms、dish_keywords，11 个大类、40–60 个细类）；高德码到自定义码的映射（三个粗码交给 LLM）；离线打标（受限标签、多标签、带证据，先人工标 50 家做金标）；菜名→菜系词表；查询展开（代码生成"细类 IN (…)"加菜名兜底）；区间规则（"左右"±20%、"以内"[0, X]、"一两百"[100, 200]、步行 N 分钟按 N×80 米）；合并流程（SQL 候选集 → 评论段语义检索 topN → 按 amap_id 取最高分收敛到店 → 只留候选集里的店 → RRF → SQL 结果太少时再放宽）。
