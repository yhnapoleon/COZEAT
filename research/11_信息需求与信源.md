# 信息需求与信源（2026-10-19）

用户定：项目不商用，合规不作为筛选条件。我保留的边界：不破解签名、不绕过登录墙和验证码，公开页面低频抓取可以做。

## 1. 每个功能需要什么信息

| 功能 | 需要的信息 | 现有来源 | 缺口 |
|---|---|---|---|
| 找餐厅 | 店名、品类、坐标、营业时间、人均、评分 | 高德 POI 2.0 | 无 |
| 找餐厅（属性条件） | 停车、包间、儿童友好、可预约、排队时长 | 高德少量 | 大，靠 UGC |
| 选套餐 | 套餐名、现价、原价、内容、适用人数、使用规则、已售 | 无 | 全部合成 |
| 对比评价 | 近期评价、推荐菜、避雷点、适合场景（约会、聚餐、带老人小孩、一人食） | Stanford 点评评论 | 大：Stanford 评论带年份的集中在 2014 年，其余推测为 2015 年前后抓取，深圳很多店已关 |
| 推荐理由 | 推荐菜、场景、口碑原话 | 高德 tag（美食 POI 下是特色菜） | 场景和原话靠 UGC |
| 看榜单 / 热门 | 近期热度、趋势、榜单名单 | 博查、心动榜媒体稿 | 门店级热度没有来源 |
| 路线规划 | 坐标、路线、时长 | 高德 | 无 |

结论：缺的都是 UGC 类信息（近期评价、推荐菜、场景、热度、团购价）。门店基础数据由高德解决。

## 2. 如果拿到抖音开放平台权限，该取什么

| 接口 | 取什么 | 用途 |
|---|---|---|
| 视频搜索 `aweme.dy.video_search` | 每店查"店名 + 商圈"，半年内、按点赞排序：视频数、点赞总和、最新发布时间、前 3 条标题与 `high_quality_text`、链接 | 门店热度、近期趋势、卡片上"去抖音看探店视频" |
| POI 搜索 `poi.search` | poi_id、名称、地址、坐标 | 和高德门店对齐，生成抖音门店页链接 |

即使拿到这两项，团购也拿不到：团购数据在生活服务 OpenAPI 里，只对商家和服务商开放，而且只能查自家门店。个人主体只能建小程序，这两项权限挂在移动/网站应用下（见 research/06 与 2026-10-19 的核实）。

## 3. 信源核实结果

### 3.1 火山方舟联网内容插件：拿不到

- 抖音资源现行文档只写"抖音 App 提供的 B2B 合规的百科词条"，`sources` 里 `douyin` 的说明是"抖音百科"。升级指南价目里出现过"抖音视频、西瓜视频"，现行功能说明没有，几份文档互相矛盾。6 元/千次，无免费额度。
- 只支持 Responses API，返回模型回答加 `url_citation`（title、url、site_name、publish_time、summary、cover_image），没有作者、点赞、POI、团购字段，也不能只取检索结果。
- 联网问答 Agent 的抖音视频卡片、兴趣地图 POI 接口都要企业认证加商务对接。
- 联网问答 Agent Pro 的"生活服务"声称能输出 POI 名称、地址、评分、人均，但只出现在模型总结文本里，数据来源没写。
- 来源：volcengine 文档 82379/1338552、82379/1338550、82379/1756990、85508/2479857，经 `https://www.volcengine.com/api/doc/getDocDetail?LibraryID=..&DocumentID=..&type=online&lang=zh` 取全文。

### 3.2 豆包搜索 Custom 版：可作为发现入口

- 结构化网页列表：Title、SiteName、Url、Snippet、Summary、Content、PublishTime 等；`Filter.Sites` 可限定最多 20 个域名。不能指定抖音内容源。
- 个人认证账号每月 500 次免费（2026-03-17 起），之后 0.02 元/次。
- 用途：`Filter.Sites=xiaohongshu.com` 加"深圳 + 商圈 + 品类"查询，拿小红书笔记链接。它是否收录小红书笔记还没实测，要有 key 才能测。备选是百度千帆搜索（小红书 robots 放行 Baiduspider）和博查。

### 3.3 扣子官方插件经开源版接入：走不通

- 开源版通过 `COZE_SAAS_PLUGIN_ENABLED`、`COZE_SAAS_API_KEY` 转发到 coze.cn，只能列出和调用付费插件；个人免费版 QPS 为 0，个人付费版每月 1000 次。
- 商店里没有点评、美团、本地生活类插件。火山联网问答 30 积分/次，返回网页摘要。

### 3.4 小红书：最有价值，已实测

- 笔记页 `https://www.xiaohongshu.com/explore/<id>` 不登录、不带 Cookie、不带 xsec_token，普通 GET 返回 200。`window.__INITIAL_STATE__` 里有 note 对象，字段：title、desc（完整正文）、interactInfo（点赞、收藏、评论、分享）、tagList（话题）、time、lastUpdateTime、ipLocation、imageList、user。没有 POI 字段；评论列表是异步加载，不在 HTML 里。
- 2026-10-19 实测 3 篇深圳餐饮笔记，发布于 2025-11、2026-05、2026-07，正文约 1000 字。内容里有店名和分店、地址、人均（"寿司郎 60r/人"）、推荐菜（"招牌辣椒炒牛肉"）、排队（"15:30 拿号 18:30 才吃上"）、场景（"带老人或小孩""一人食友好"）。
- 搜索页没测，robots 对所有爬虫都没放行 /search_result，推测需要登录和签名，不碰。发现笔记靠第三方搜索。
- 风险：平台随时可能给笔记页加 xsec_token 校验或登录墙；高频访问会触发验证码。对策是只在离线 ETL 里低频抓取并缓存，运行时不依赖。

### 3.4b 大众点评与美团（2026-10-19 实测）

- 抖音视频搜索只给标题、点赞、链接和一个说明不清的 `high_quality_text`，拿不到视频内容和评论，只能算热度，不能当评价。
- 搜索引擎收录了点评门店页，标题形如"【店名】电话_地址_价格_营业时间_商圈品类团购"，摘要里有星级和人均。这是快照，可能过期，但能通过搜索 API 拿到。
- 直接打开点评门店页：手机版、电脑版、带 `msource=applemaps` 的版本，三种都跳到 `verify.meituan.com ... action=spiderindefence` 的验证页。要过验证码，不做。
- 美团 SEO 页：团购页 `sz.meituan.com/meishi/d<id>.html` 跳到活动页，门店页 `sz.meituan.com/cate/<id>/` 返回 404。搜索引擎里留的是旧快照。
- **点评探店笔记页 `m.dianping.com/discovery/<id>` 普通 GET 返回 200。** 页面里有完整正文、发布时间、评论，以及结构化的 `relateShopInfoList`：shopId、shopName、branchName、mainRegionName（商圈）、mainCategoryName（品类）、shopPower（星级，50 即 5 星）、avgPrice（人均）。不用模糊匹配就能对上门店，还顺带拿到点评的星级和人均。
- 新鲜度：搜索结果里深圳探店笔记的日期集中在 2020–2025 年，实测那篇是 2021-11。比小红书旧，数量待测。

## 4. 结论：信源组合

| 信息 | 主信源 | 补充 |
|---|---|---|
| 门店基础、评分、人均、营业时间、坐标 | 高德 POI 2.0 | 百度地点检索交叉验证 |
| 推荐菜 | 高德 tag + 小红书笔记抽取 | |
| 近期评价、场景、避雷、排队 | 小红书笔记抽取 | 点评探店笔记（自带门店对象）；Stanford 只留作切分实验语料 |
| 点评星级与人均 | 点评探店笔记的 relateShopInfoList | 搜索 API 返回的点评门店页摘要 |
| 热度 | 小红书提及数、点赞收藏、发布时间 | 抖音视频搜索（如导师能提供企业主体应用） |
| 团购 | 合成（标注） | 小红书笔记里提到的团购价作为校准 |
| 榜单 | 心动榜媒体稿 + 小红书"人气榜"类笔记 | 博查实时 |

小红书覆盖的信息比抖音视频搜索更全：后者只给标题、点赞和一段文本，前者有完整正文。抖音信号的价值在于"抖音本地生活"这个题目本身，拿不到就在 PRD 里说明替代方式。

## 5. 小红书管线

1. **发现：** 约 450 条查询（3 个区 × 约 15 个商圈 × 10 个品类或场景），每条取 10 个结果，去重后预计 2000–3000 篇笔记。搜索 API 用豆包搜索 Custom（每月 500 次免费正好够一轮），备选百度千帆。
2. **抓取：** 笔记页普通 GET，每 4 秒一次，失败重试一次，原始 HTML 缓存到 `data/raw/xhs/`。3000 篇约 3.5 小时，后台跑。
3. **抽取：** LLM 逐篇抽成 JSON：[{店名, 分店, 区, 地址片段, 人均, 推荐菜[], 场景[], 排队, 避雷, 团购提及, 情感, 原话片段}]。一篇笔记常提到多家店。
4. **对齐：** 用高德关键字搜索"店名 + 区"，再用 rapidfuzz 比对名称和地址，得到 amap_id；对不上的丢弃。
5. **聚合：** 每店：笔记数、点赞收藏总和、最近发布时间、推荐菜频次前 5、场景标签、人均中位数、原话片段若干条，附原笔记链接。
6. **入库：** 聚合字段写 shop 表；原话片段写 KB-review，前缀"amap_id | 店名 | 商圈 | 品类 | 来源 小红书 | 日期"。
